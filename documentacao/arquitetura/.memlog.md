# Memlog de arquitetura

decision: AD-1 — Paradigma de SPA pública com cálculo determinístico no front-end; Binds: entrega inicial focada em navegação pública e ranking; Prevents: backend obrigatório antes do produto validar experiência e método.
decision: AD-2 — Separação estrita entre apresentação, domínio e dados; Binds: UI não resolve lógica de negócio; Prevents: drift de cálculo e inconsistência entre telas.
decision: AD-3 — Transparência da metodologia é invariável; Binds: critérios, pesos, fontes e atualização devem ser sempre visíveis; Prevents: arbitrariedade percebida e baixa confiança do usuário.
decision: AD-4 — Personalização por perfil do eleitor é parte da experiência; Binds: para qualquer perfil, a nota final permanece comparável; Prevents: pesos ocultos e comparações inválidas entre perfis.
decision: AD-5 — Dados públicos e versionados são base de confiança; Binds: cada número precisa de origem e metadados; Prevents: dados sem rastreabilidade e inconsistência de fonte.
decision: AD-6 — Mock atual e pipeline futuro; Binds: dados podem iniciar em fixtures e evoluir para API; Prevents: dependência prematura de infraestrutura.
decision: AD-7 — Ranking como vista sobre entidades dominantes; Binds: parlamentar, critério, nota, peso e fonte formam o modelo central; Prevents: duplicação e divergência de campos entre telas.
decision: AD-8 — Integração por pipeline de dados e não por consulta direta do front-end; Binds: APIs oficiais passam por backend de ingestão antes da UI; Prevents: instabilidade, rate limit, falta de rastreabilidade e inconsistência de origem.
decision: AD-9 — PostgreSQL como banco principal do sistema; Binds: persistência relacional, histórico e auditoria de métricas e fontes; Prevents: perda de integridade e reprocessamento impossível.
version: React 18 / Vite 5 / JavaScript — stack escolhida para baixa fricção, entrega rápida e boa evolução incremental.
version: PostgreSQL 16 recomendado para a produção de dados públicos e auditáveis.
event: arquitetura spine finalizada para a iniciativa de avaliação de parlamentares.
event: proposta de APIs oficiais e banco de dados registrada para integração do produto.
